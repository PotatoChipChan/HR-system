# Changelog

All meaningful changes to this project should be documented here.

## Unreleased

### Added

- Job posting soft delete (archive): Admin and HR Manager can delete a job posting when no interviews have been scheduled for any of its applications. Deletion is a soft delete — the posting gains an `Archived` status, is hidden from the active and closed posting lists, stops accepting public applications (404 with a "no longer accepting applications" message) and keeps its row and all related records. The delete button lives on the posting page with a confirmation dialog and is never shown for archived postings; the route re-checks the interview guard server-side (`DELETE_POSTING` audit event). Postings become `Archived` automatically when the last approved opening is filled (replacing the old `Filled` terminal state; `closed_at` is kept). `migrate_job_posting_archive` (backup-guarded table rebuild, idempotent) adds `Archived` to the status CHECK and backfills existing `Filled` postings; plain HR has no delete permission.
- Regression coverage (B36, 14 checks): migration guard/backfill/idempotency/backup, Admin and HR Manager delete, interview guard blocking, list hiding, badge and button visibility, plain-HR denial, and public apply rejection.
- Branch-dependent interviewer assignment: Physical interviews restrict the interviewer panel to active eligible staff physically assigned to the posting branch (branch Managers, Admin, HR, HR Manager), while Virtual interviews keep the company-wide roster (posting-branch Managers + Admin/HR/HR Manager). The manager who requested the position via the earliest approved vacancy request is listed first with a "(Requester)" label in scheduling UIs and is prioritised first by auto-assign (only when active and eligible for the format). Postings whose branch has no local interviewers cannot schedule Physical (manual, bulk, and auto-assign all block with "This branch has no eligible local interviewers. Schedule as Virtual instead.", and the UI disables the Physical option with an inline hint). Every scheduling path validates the submitted interviewer set against the format-specific pool server-side; forged IDs keep the original "active interviewers from your company" check. HR Manager can auto-assign interviews but is denied manual and bulk scheduling (route-level guards). No schema change.
- Regression coverage (B35, 29 checks): pool membership semantics, requester resolution/ordering, manual/bulk/auto-assign format validation, empty-branch blocking, optional-interviewer behaviour, UI requester label and disabled Physical option, and HR Manager permission guards.

- Branch-filtered direct posting form: selecting a Branch in the job-posting form client-side filters the Department dropdown to that branch's departments (options for other branches are hidden and disabled; a now-mismatched selection is cleared). Every company department appears in the dropdown — including departments with no catalog positions yet, where an inline hint directs the user to add a title under Roles &amp; Permissions → Position Catalog first. Field order is Branch + Employment Type, then Department + Job Title.
- Number of Openings on the direct posting form (1–50, server-validated with the vacancy-request bounds): the posting stores `approved_openings` so manually created postings support the same multi-opening lifecycle (reserve → fill → Partially Filled → Filled) as approved vacancy requests; omitted openings default to 1.
- Position-less department visibility: Department Manager Assignments now lists every department (LEFT JOIN) with an `Unassigned` badge when no manager is set, and the Position Catalog names departments that have zero active catalog positions with a link to the add-position form.
- Server-side rules unchanged: a valid active catalog position is still required, and branch, department, position, and company must agree (crafted mismatches remain rejected with no posting created).
- Regression coverage (B30): form attributes, openings input and validation (0/51/non-numeric rejected, default 1, multi-opening persistence), position-less department visibility in the posting form and roles page, Unassigned rendering, empty-departments hint, valid posting persistence, and crafted mismatch/position-less rejections — all against a disposable database copy.
- Offer approval gate: HR/Admin request approval; HR Manager/Admin approve or reject (reason required) before an offer can be sent (`Offer_Approval`). Send without approval is blocked.
- Opening reservation lifecycle: an approved offer reserves an opening only when delivery succeeds; delivery failures are logged (`Email_Delivery_Log`) and retryable without consuming an opening; acceptance keeps the reservation; decline and expiry release it (reason recorded); hire confirmation fills it. Approved pending offers cannot exceed unfilled openings.
- Server-side offer expiry: a background scheduler (`offer_expiry.py`) marks expired Sent contracts `Expired`, applications `Offer Expired`, releases reservations and notifies HR/Admin + HR Manager. QA 1-minute expiry via `OFFER_EXPIRY_MINUTES` is honoured only in development/test; production uses the standard 7 days. Expiry never sends a replacement offer automatically (replacement goes through scorecard ranking → HR Manager confirmation → offer approval → send).
- Hire confirmation separated from acceptance: acceptance keeps the application `Offered` (reserved), and HR Manager/Admin confirm the hire (role-gated) — the candidate becomes `Hired` and one opening is filled; remaining candidates are rejected only when all openings are filled.
- New `migrate_offer_lifecycle` migration (verified rebuilds of `Contract`/`Job_Application` status CHECKs derived from the live table, backup first) plus `Offer_Approval` and `Email_Delivery_Log` tables.
- Regression coverage (B21): approval gate, reservation on successful delivery, failure/retry, decline/expiry releases, no auto-replacement, multi-opening hire and rejection-on-fill, and hire role gating.

- Fixed interview scorecards (`Interview_Scorecard`): exactly three non-customisable 1–5 criteria (technical/role competence, communication/collaboration, role fit/professionalism), each with a mandatory evidence note, recorded only by Admin/HR for completed interviews. No "confidence" criterion.
- Scorecard-based candidate ranking: computed per posting from completed scorecards and displayed on the posting page; it never hires or sends an offer automatically.
- Audited candidate selection (`Candidate_Recommendation`): an HR Manager confirms a highest-scoring candidate directly; the acting user and timestamp are recorded before contract work can begin.
- New `migrate_scorecard_recommendation` migration (additive, no backup) creates both tables.
- Regression coverage (B20): scorecard validation and recording, ranking ordering, retired manual recommendation, lower-score rejection, and HR Manager top-score confirmation.

- Conflict-safe scheduling: the auto-assign slot finder now checks the live `Interview` table (all Scheduled/Confirmed interviews, overlap-aware by start/end times) for every candidate slot, not just batch-local slots and leave; manual scheduling and bulk scheduling also reject slots where any selected interviewer is already booked (panel availability), and rescheduling reuses the same overlap helper.
- Auto-assign enforces one job posting per batch (preview and confirm reject mixed-posting selections); confirmation tracks and reports candidates skipped due to conflicts and records them in the audit event.
- Regression coverage (B19): overlap-helper semantics, one-posting enforcement, no-double-booking property across all scheduled interviews, and email delivery in local-capture mode (stubbed sender — no real bulk emails).

- Interview format/venue rules: every scheduled interview (manual, bulk, auto-assign) requires a `Physical` or `Virtual` selection. Physical interviews automatically use a snapshot of the posting branch's address (blocked if the branch/address is missing); Virtual interviews require a meeting link and show no physical venue. Format, venue snapshot and posting branch are stored on the interview record and revalidated on confirmation.
- Interview rescheduling: HR/HR Manager/Admin (inherited permission) can reschedule future Scheduled/Confirmed interviews with a required reason; old/new datetime, reason and acting user are recorded in a new `Interview_Reschedule` table plus audit log; slot validity (weekends, policy hours, interviewer leave and existing bookings) is revalidated and the original interview is left unchanged when no valid slot exists; Completed/Cancelled interviews cannot be rescheduled; updated invitations are emailed.
- Candidate interview-reschedule emails now surface as a manual-review HR notification only — interviews are never changed by email (`detect_reschedule_request` + `surface_reschedule_request` in the email monitor). Every interview invitation now carries an `INT-<id>` reference and candidates are asked to keep it in replies; the scanner matches the exact interview when the reference is retained, otherwise it creates a generic notification listing all of the sender's upcoming interviews for HR to choose — it never guesses. Deduplication is persistent in SQLite (`Reschedule_Email_Processed`, `migrate_reschedule_dedup`) so a restart cannot re-notify for the same Message-ID within the scan window; rows older than 30 days are pruned.
- New `migrate_interview_format` migration (additive, no backup needed) adds `format`/`venue`/`posting_branch_id` to `Interview` and creates `Interview_Reschedule`.
- Regression coverage: B16 (migration), B17 (venue rules, blocking, rescheduling behaviour), B18 (email reschedule detection and notification, no interview mutation).
- Informational "Auto-shortlisting rule" card on the Applications page (HR/Admin roles only) explaining the actual auto-shortlisting formula, thresholds and evidence prerequisites. The displayed values are derived from `scorer.py` constants (`SHORTLIST_THRESHOLD`, `MIN_COVER_LETTER_CHARS`, `MIN_RESUME_CHARS`) via `screening_rule_info()`; no scoring behavior changed.
- Regression coverage (B15) proving the rule card renders for HR and Admin and is hidden from Manager, Employee, and unauthenticated users.

- Vacancy opening ledger (`migrate_vacancy_openings` migration): `Job_Posting` gains `approved_openings`/`reserved_openings`/`filled_openings` and a `Partially Filled` status; `Vacancy_Request` gains `requested_openings`/`approved_openings`; new `Opening_Reservation` table. Historical rows backfilled (postings 1/1, filled=1 where Filled; Approved requests 1/1; Filled reservations for existing Hired applications).
- Vacancy request form now captures the requested number of openings (1–50, validated server-side); approval carries the count to the posting.
- Opening accounting in `close_job_posting_for_application`: filling one opening updates the posting status (Open/Partially Filled/Filled, with `closed_at` set when fully filled) and rejects the remaining active candidates only when all approved openings are filled (emails isolated per candidate, audit event).
- Posting-status filters across careers, internal job board, public apply, bulk schedule, and email intake now treat `Partially Filled` postings as accepting applications.
- Regression coverage: B11 (vacancy-openings migration on a temp copy — backup, full preservation, backfills, idempotency) and B12 (multi-opening ledger lifecycle through routes); `tests/test_recruitment_posting_closure.py` updated to the new opening semantics.

### Changed

- Candidate selection is now scorecard-only: normal HR completes scorecards, the completed-scorecard totals rank candidates, and an HR Manager can directly confirm only a highest-scoring candidate (ties are eligible) from the application page. This writes the approved, audited `Candidate_Recommendation` record and immediately enables contract preparation. The manual recommendation and separate selection-approval actions are retired.
- Retired the HR Director system role. Legacy HR Director accounts are migrated to HR Manager with the HR Manager role's full Admin-equivalent permission set; the System Roles catalog now presents five fixed roles and describes HR Manager as full system access.
- Removed first-hire posting closure: a posting is no longer set `Filled` when the first candidate is hired; it becomes `Partially Filled` until all approved openings are filled.
- Recruitment decision flow is now scorecard-led: legacy Interview Pass/Fail actions are retired and harmless; a past scheduled interview is marked `Completed` without changing the application or other candidates. A completed scorecard is required before the HR Manager can confirm a highest-scoring candidate.
- Contract departments are displayed from and enforced from the related job posting; a submitted `department_id` is ignored. Admin and HR Manager can send an offer directly after candidate-selection approval, while normal HR still needs the separate offer-send approval.

### Fixed

- Guided organisation-to-recruitment setup: HR can continue from Branch → Department → Position → a prefilled Manager employee → a prefilled Job Posting. Position and posting setup also round-trip safely through Add Department/Add Position while preserving selections; external return destinations are rejected. Optional Gender, IC, and Passport values are stored as `NULL` when omitted, and the employee form preserves the selected submit action. B39 regression coverage protects the full handoff.
- Leave approval no longer changes a future employee's durable employment status to `On Leave`. Dashboard and profile leave indicators now derive from approved leave dates, and employee leave cards explicitly show reserved pending days. B25 regression coverage verifies the corrected flow and the HR deactivation path.
- Attendance Logs summary cards now use the same role scope and active filters as the records table. Managers and employees no longer see zeroed summaries above visible records, and the HR method filter is reflected in the totals. B40 regression coverage protects both cases.
- UX audit repairs: the performance-review header cards now use the same company/branch scope as the table (so a Manager no longer sees company-wide aggregate counts); the Days Present column now shows its approved-attendance evidence; and Audit Log pagination is compact, handles malformed/out-of-range pages, and preserves every active filter while paging.
- Organisation setup is now connected at the point of need: a job posting for a branch with no departments offers a prefilled Add Department path; Branches link to their filtered Departments; Departments link to a prefilled Add Position Title form; and Roles & Permissions has a concise setup shortcut bar. The required catalog-position workflow and server-side validation remain unchanged.
- Invoice OCR guidance now consistently refers to an invoice file, matching the JPG, PNG, and PDF upload options. Salary Increment pages clarify that the current policy is the default for new proposals while existing proposals retain the percentage stored with them.

- Recruitment UX follow-up: restored the shortlisted-candidate bulk action bar by keeping its JavaScript inside the page script block; HR Managers no longer see the manual scheduling control they are not permitted to use; Manager application filters now contain only their visible branch/department scope; and the branch-scoped dashboard headcount now says "In your branch". Interview invitations no longer contradict their confirmation instruction: their footer states that replies are monitored. B24, B26, B31, and B35 regression coverage protects these behaviours.

- The candidate offer-acceptance pages (`/recruitment/contract/<id>/accept`) no longer render inside the app shell: `accept_confirm.html` and `offer_accepted.html` are now standalone public pages (careers-page style, self-contained styling, no sidebar/navigation/notification chrome). Forms, CSRF, token validation, file upload, and server-side behavior are unchanged; B21 regression asserts the accept page renders standalone.

- Multi-opening selection confirmation: the HR Manager can now confirm candidates in scorecard-ranking order up to the posting's unfilled approved openings (top N for an N-opening posting; ties at the cutoff stay eligible, and the offer-send reservation gate still caps pending offers). Previously only the single highest scorer (or a tie) could ever be confirmed, stranding the remaining openings. B20 regression covers second-highest confirmation, tie eligibility, below-slot blocking, and the no-confirmations-after-all-openings-filled rule.

- Interview scorecards are now immutable: the first recorded decision is final — re-submission is rejected server-side ("the first decision is final") and the scorecard UI renders existing scorecards read-only with no Update form. The previous UPSERT re-submission path is removed. B20 regression updated to assert the fixed-decision behavior.

- Auto-assign interview modal no longer jumps while typing the meeting link: the link input now recalculates the slot preview on a 500ms debounce (instead of every keystroke), an existing preview stays on screen during recalculation instead of collapsing to a loading line, and the modal overlay is top-anchored so content growth does not re-center the dialog. Regression coverage (B31) asserts the three stability markers.

- Face attendance manual fallback now supports check-out: `/face/attendance` treats the employee as checked in whenever an open check-in exists (today or the previous calendar day) instead of trusting the newest record of the day, so after 3 biometric failures the fallback renders a Manual Check-Out request; `manual_self` closes the actual open record (including cross-midnight open check-ins from yesterday), rejects a check-out timestamp at or before the check-in time, and rejects check-in while an open check-in exists. Camera-start failures are now counted server-side so the fallback gate stays consistent.

- Broad QA hardening: employee profile changes now require a full name; expense claims reject negative amounts and zero totals before a record or file is created; Payroll, Performance, Reports, Increment, Bonus, and Year-End period/filter inputs safely reject malformed or out-of-range numeric values instead of producing 500 errors. Compensation/bonus policy values are range-validated before saving.
- Access-control hardening: the performance-score API now enforces Employee self-only and Manager branch-only access. A crafted Manager employee-edit request cannot alter the hidden branch, department, or role assignment; submitted branch/department/role combinations are validated for every edit.
- Regression coverage: B24 (41 assertions) exercises non-face Admin sidebar pages, malformed input, role/scoping boundaries, and sensitive-record access; B25 (11 assertions) exercises leave, claims, payroll, performance, increment/bonus approvals, report export, and notifications. Both run against disposable database copies with local notification/email capture.
- QA validation hardening: manual and bulk interview scheduling now reject malformed/past datetimes, weekends, out-of-policy hours, non-positive durations, and forged/inactive interviewers; the reschedule date picker and bulk date picker prevent choosing an earlier calendar day while the server remains authoritative.
- Direct job postings and vacancy requests now reject malformed, negative, and inverted salary ranges; contract drafts validate dates, working-time fields, and non-negative salary; Interview Policy validates its stated numeric/time bounds; malformed internal-applicant IDs, leave fields, and email-server ports produce clear validation messages instead of 500 errors.
- B23 field-validation regression coverage now uses a disposable database copy and stubs outbound email. B11 now clears `Candidate_Recommendation` in its legacy migration fixture so later recruitment data cannot introduce foreign-key violations during the old-schema rebuild test.
- The generic recruitment status endpoint can no longer set `Interview`, `Offered`, or `Hired` from a crafted request. Those states are now server-controlled by their dedicated scheduling, offer, and hire workflows; the existing visible manual transitions (`New`/`Shortlisted`/`Rejected`) remain available.
- Contract editor pages now match their server rule: only a `Draft` contract is editable. Sent, accepted, signed, declined, and expired contracts show a clear read-only state and direct users back to the application’s Contract / Offer section.
- Mobile-width visual QA: wide data tables across the dashboard, organisation directories, roles/catalogue, attendance, leave history, invoices, claims, performance, recruitment, reports, audit trail, and employee pages now stay inside accessible horizontal scroll containers instead of widening the page. Their filters and toolbars wrap cleanly at narrow widths.
- Compensation Policy no longer nests a GET form inside its save form; its year selector now performs a safe GET navigation, and its fixed four/three-column field grids stack into usable two-column groups on phones.
- Interview scheduling and rescheduling now reject any slot at or before the server's current time (the next minute remains valid); completed-interview applications cannot be scheduled again and no longer show obsolete interview actions.
- The full regression suite now runs on one temporary database snapshot, so its fixtures, migrations, notifications, and recruitment requests cannot affect the development database. Email paths used by recruitment lifecycle tests are captured locally. Console-safe test output also prevents Windows legacy encodings from aborting a run.
- Added B22 regression coverage for retired Pass/Fail safety, completed-interview action gating, posting-derived contract department enforcement, direct-offer role rules, generic-status workflow protection, and read-only sent-contract editing. Full suite: 233 checks.
- AI scorer initialization now has a small built-in English stopword fallback when the optional NLTK corpus is absent, preserving the configured scoring formula while allowing a clean development/test environment to run.
- Added `migration_framework.py`: reusable, assertion-guarded table-rebuild helpers (`backup_database`, `backup_before_migration`, `get_table_info`, `rebuild_table`) with row-count parity, full-row preservation, `PRAGMA foreign_key_check`, and index/trigger restoration checks plus transactional rollback on failure.
- Pending rebuild migrations (`migrate_attendance_status`, `migrate_contract_security`) now create a timestamped, never-overwriting backup in `<db parent>/backups/` before rebuilding, and abort if the backup fails; already-applied no-op runs create no backups. Backup retention/cleanup policy documented in `MIGRATIONS.md`.
- `migrate_contract_security()` refactored onto `rebuild_table()` (removed its manual copy/drop/rename transaction), gaining the framework's row-preservation, foreign-key, index, and trigger assertions; Contract migration regression coverage added (B10: backup creation, full-row preservation, FK checks, idempotency, no backup on no-op).
- Added `MIGRATIONS.md` migration runbook (backup-before-migrate, verification steps, rollback procedure, testing guidance).
- Added framework regression tests (B8) covering backup consistency, full row/index/trigger preservation, and rollback verification.

### Fixed

- Fixed CSRF rejection when confirming auto-assigned interviews from the Applications page: programmatic `form.submit()` calls now receive the CSRF token via a patched `HTMLFormElement.prototype.submit` in the base template interceptor (also protects other scripted form submissions such as payroll bulk finalise, bonus/increment bulk actions, year-end review, and organisation delete actions).
- Attendance security and correctness fixes:
  - Employees can no longer view or export other employees' attendance records (logs now scope to the logged-in employee; IDOR filter parameters are ignored).
  - Fixed the Attendance Logs route/template variable mismatch (`records`/`selected_*` vs `logs`/`emp_filter`/`method`/`branch`) so the table renders, filter selections persist, and the CSV export link preserves active filters.
  - Attendance `Rejected` status is now supported by the schema (idempotent `init_db` migration); pending-review rejection retains the row.
  - HR manual attendance now targets a selected employee (with company/branch validation) instead of silently recording for the logged-in HR user; the duplicate check-in guard now uses the submitted attendance date rather than today's date.
  - The attendance status migration now preserves rows/IDs/foreign keys, restores the dropped `idx_attendance_employee` / `idx_attendance_checkin` indexes (including for already-migrated databases), and asserts row-count parity plus `PRAGMA foreign_key_check` before commit. It now runs through `migration_framework.rebuild_table`.
  - The B7 migration test now compares every preserved `Attendance` column (check-in/out, hours, overtime, confidence, status, manual flags, reason, correction metadata, timestamps), not just a column subset.
  - Attendance regression tests (B6) run against an isolated temporary copy of the database so fixture creation/deletion never touches real development data.
